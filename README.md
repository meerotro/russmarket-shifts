# График смен

Тестовое задание Fullstack-разработчика: интерфейс создания графика смен сотрудников по макетам
Figma. Vue 3 + TypeScript на фронте, Laravel + PostgreSQL на бэке.

- Сайт: https://aleksbar291297.alwaysdata.net
- Витрина UI-кита: https://aleksbar291297.alwaysdata.net/ui-kit
- Спецификация и решения по неоднозначным местам макета: [docs/spec.md](docs/spec.md)

## Что умеет

- Сетка «сотрудники × дни» в режимах «Неделя» (время и часы) и «Месяц» (только часы), навигация
  по датам, поиск по ФИО.
- Назначение смены тремя способами: клик по ячейке, клик по дате (на весь день), выделение
  нескольких ячеек (Ctrl/Shift+клик или протягивание) и панель действий.
- Шаблоны «Утро / День / Вечер» и своя смена с произвольным временем, включая ночные.
- Drag-and-drop: шаблон в ячейку, смена между ячейками (с Ctrl — копия).
- Строка «Покрытие», счётчики на шаблонах и часы сотрудника пересчитываются сразу.
- Правки копятся в черновике; «Сохранить» отправляет их одним запросом, «Опубликовать» сохраняет
  и публикует период. Предупреждение при уходе с несохранёнными изменениями.

## Стек и почему так

| Решение                                  | Причина                                                                 |
| ---------------------------------------- | ----------------------------------------------------------------------- |
| Одно приложение Laravel отдаёт API и SPA | Один деплой и один домен: без CORS и второго хостинга                   |
| PostgreSQL                               | Как в продакшене вакансии; тесты идут на той же СУБД, что и боевой сайт |
| Pinia + composables                      | Состояние и правила живут отдельно от компонентов и тестируются без DOM |
| Свой UI-кит на CSS-переменных            | Токены сняты с макета; компоненты не знают о предметной области         |
| Без очередей и WebSocket                 | Бесплатный хостинг не разрешает фоновые процессы                        |

## Архитектура фронтенда

```
resources/js/
  api/          единственный HTTP-клиент (ApiError), типы ответов, эндпоинты
  lib/          чистые функции: время и длительность, даты и периоды, ключи ячеек
  stores/       schedule.ts — данные графика и черновик изменений
  composables/  период (в URL), выделение, покрытие, часы, drag-and-drop, debounce
  ui/           кнопка, поиск, переключатель, аватар, бейдж, поле времени, поповер, меню, иконки
  components/   schedule/ — сетка, ячейка, панель выделения, шаблоны; layout/ — каркас
  pages/        SchedulePage, UiKitPage, HomePage
```

Ключевая идея — **черновик в сторе**. `serverShifts` хранит то, что лежит на сервере, `draft` —
только изменённые ячейки (значение или `null` для удаления). Сетка читает их слияние, поэтому
покрытие, часы и счётчики — обычные `computed` без отдельного состояния. Ячейка, возвращённая к
сохранённому значению, из черновика исчезает. При ошибке 422 сообщения привязываются к ячейкам по
индексу элемента в запросе.

Страница только связывает стор, composables и компоненты; расчётов в компонентах нет.

## API

| Метод | Путь                     | Назначение                                              |
| ----- | ------------------------ | ------------------------------------------------------- |
| GET   | `/api/employees?search=` | Сотрудники, поиск по ФИО без учёта регистра             |
| GET   | `/api/shift-templates`   | Шаблоны смен                                            |
| GET   | `/api/shifts?from=&to=`  | Смены и опубликованные дни периода                      |
| PUT   | `/api/shifts`            | Пакет изменений `{ upsert, delete }` в одной транзакции |
| POST  | `/api/schedule/publish`  | Публикация периода                                      |

Пакетное сохранение — «всё или ничего»: ошибка в одной смене откатывает весь запрос. Ссылки на
сотрудников и шаблоны проверяются двумя запросами на пакет, а не двумя на элемент. Длительность
смены считается в одном месте (`App\Services\ShiftDuration`), на фронте её зеркалит `lib/time.ts`.

## Допущения по макету

Полный список — в [docs/spec.md](docs/spec.md). Главное:

- **Одна смена на сотрудника в день**; новая смена в занятой ячейке заменяет старую.
- **Длительность считается из времени.** В макете встречаются «08 - 18 / 8 ч» и
  «Вечер 15:00–23:00 · 9 ч» — это неточности.
- **Число на карточке шаблона** — сколько смен по шаблону стоит в видимом периоде. В макете оно
  противоречиво (1 / 2 / 3 на пустом графике).
- **«агент · 24 ч»** — сумма часов сотрудника за видимый период.
- **Ночные смены разрешены:** конец не позже начала означает «до следующего дня».
- **Цвета:** Утро — голубая, День — сиреневая, Вечер — мятная, своя смена — сплошная синяя.
- **Клик по дате** выделяет день у видимых сотрудников и открывает меню быстрого назначения.
- **Навигации по датам в макете нет**, а в тексте задания есть — добавлена справа от переключателя.
- **Статус периода**, кнопка «Отменить изменения» и точка на несохранённой смене добавлены, чтобы
  черновик был виден.
- Вместо фотографий сотрудников — инициалы.
- Доступа к Dev Mode в Figma не было: цвета и размеры сняты с холста, подобранные на глаз
  значения перечислены в [design/tokens.md](design/tokens.md).

## Запуск локально

Нужны PHP 8.3+, Composer, Node 22, PostgreSQL.

```bash
cp .env.example .env        # указать DB_PASSWORD
sudo bash scripts/setup-local-db.sh   # Ubuntu/WSL: PostgreSQL, роль и базы (рабочая и тестовая)
composer setup              # зависимости, ключ, миграции с демо-данными, сборка фронта
composer dev                # http://localhost:8000
```

## Тесты и проверки

```bash
php artisan test            # бэкенд: Pest на PostgreSQL
npm test                    # фронтенд: Vitest
npm run typecheck           # vue-tsc, strict, без any
npm run lint && npm run format:check
vendor/bin/pint --test
```

Те же проверки и сборка идут в GitHub Actions на каждый push.

Бэкенд: каждый эндпоинт, валидация, откат транзакции, поиск, публикация, расчёт длительности.
Фронтенд: стор (черновик, пакет изменений, ошибки 422, гонка с ответом сервера), выделение
ячеек, покрытие, часы, время и даты, ключевые компоненты.

## Деплой

Сборка локально, один архив по SSH, на сервере — только `composer install`, миграции и кэш.
Подробности — [docs/deploy.md](docs/deploy.md).
