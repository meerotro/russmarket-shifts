# Деплой на alwaysdata

Бесплатный тариф не разрешает фоновые процессы и долгие задачи, поэтому на сервере нет очередей
и воркеров, а фронтенд собирается локально: на сервер уходит один архив с готовой сборкой.

## Один раз: панель alwaysdata

1. **Databases → PostgreSQL → Add a database.** Имя — `<аккаунт>_russmarket`. Пользователь базы —
   существующий `<аккаунт>` или новый; пароль задаётся здесь же.
2. **Web → Sites → (сайт по умолчанию) → Edit.** Type — `PHP`, Root directory —
   `/russmarket/public/`, версия PHP — 8.3 или новее.
3. **SSH:** доступ по ключу (Remote access → SSH → добавить публичный ключ) либо по паролю.

## Деплой

```bash
DEPLOY_HOST=<аккаунт>@ssh-<аккаунт>.alwaysdata.net bash scripts/deploy.sh
```

Скрипт:

1. собирает фронтенд (`npm run build`);
2. упаковывает файлы, нужные серверу: код из git без тестов, макетов, документации и исходников
   фронта, плюс `public/build`. `vendor/` и `.env` в архив не попадают;
3. загружает архив по SSH и распаковывает в `~/russmarket`;
4. на сервере: `composer install --no-dev --optimize-autoloader`, `php artisan migrate --force`,
   кэш конфигурации, маршрутов и шаблонов.

**Первый запуск** создаёт `~/russmarket/.env` из `.env.example` (production, `APP_DEBUG=false`,
адреса базы по имени аккаунта), генерирует `APP_KEY` и останавливается. Нужно зайти на сервер,
проверить `DB_*` и вписать `DB_PASSWORD`, затем запустить деплой ещё раз. Пароль существует
только в этом файле на сервере: в git и в архив он не попадает.

Демо-данные (12 сотрудников, 3 шаблона, смены на текущую неделю) загружаются так:

```bash
DEPLOY_HOST=... DEPLOY_SEED=1 bash scripts/deploy.sh
```

Сидер можно запускать повторно — дубликатов не будет.

## Размер

`vendor` без dev-пакетов — 45 МБ, код и сборка фронта — около 1 МБ.

## Проверка после деплоя

- `https://<аккаунт>.alwaysdata.net/` — страница графика;
- `https://<аккаунт>.alwaysdata.net/api/shift-templates` — JSON с тремя шаблонами;
- `https://<аккаунт>.alwaysdata.net/ui-kit` — витрина компонентов.
